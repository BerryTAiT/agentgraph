THE FRAMEWORK

What is agentgraph?

agentgraph is an open-source R package for building, running, and shipping agentic-AI workflows. You define the flow in pure R; a compiled C++20 engine executes it.

01

What it is

An agent is just a program that plans a step, calls a model for a decision, acts, and repeats. agentgraph turns that loop into a stateful graph: nodes are the steps, edges are the routing, and shared state carries the result from one step to the next.

02

What it does

It wires LLMs, tools, memory, and humans into one pipeline. One node calls a model, another invokes a tool, several run in parallel on real threads, and a router decides which branch comes next — all managed for you, all from R.

03

What it is used for

Multi-agent debates and research swarms, RAG pipelines grounded in your own documents, coding and support agents, voice assistants, and evaluation harnesses — anything where several model-driven steps must cooperate toward one outcome.

MADE OF THREE LAYERS

R APIwhat you write

Graph builders, node types, and 13 model providers — every touchpoint is plain, familiar R.

Rcpp bridgethe one seam

Auto-generated glue turns R objects into zero-copy C++ views. The bridge is crossed once per run, not per token.

C++20 enginewhere it runs

Graph executor, hand-written HTTP and streaming client, vector search, and a thread pool — no interpreter lock, no GC pause.

library(agentgraph) 8 node types 13 providers

In short: agentgraph is to R what orchestration frameworks are to Python — a place to compose reasoning, calls, and tools into one system — but with a compiled core underneath and a single language on top.

LOW-LEVEL POWER

What C and C++ actually give you

01

Manual memory control

You decide exactly when every byte appears and when it vanishes. Memory can be pooled, reused, and laid out to fit CPU cache lines. There is no garbage collector — nothing ever pauses your program mid-computation to clean up.

02

True parallelism

std::thread, atomics, and lock-free structures put every core to work at once, with no global interpreter lock serializing them. Browsers, databases, and game engines are C++ because parallelism is its native mode.

03

Zero-copy & SIMD

Pass a pointer and you pass the data itself — no duplication, no serialization. SIMD pushes 8 to 16 numbers through the CPU per cycle, and C++ drives those lanes directly. Latencies land in nanoseconds.

04

Operating-system access

Sockets, file handles, memory maps, and kernel calls are first-class citizens. The network stack belongs to your program, not to a wrapper library — nothing stands between you and the OS.

05

Deterministic latency

The same work costs the same time on every run: no interpreter jitter, no GC pause, no just-in-time warmup. Flight controls, trading engines, and medical devices are certified in C and C++ for exactly this reason.

06

Compile once, run native

The compiler emits a real machine-code binary. No runtime to install, no bytecode to interpret, no dependency graph to break — the binary you test is the binary you ship.

The proof surrounds you: Linux is ~30 million lines of C; Chrome, V8, and the engines inside Unreal and Unity are C++; and Python itself is CPython — an interpreter written in C. Everyone already runs low-level code daily; most people just never see it.

THE PRICE OF POWER

Control is a full-time job

A pointer is a loaded weapon

Nothing in C checks a pointer: no bounds, no lifetimes, no type safety after a cast. When Microsoft and Google each audited their own C/C++ codebases, they reached the same conclusion — about 70% of critical security vulnerabilities trace back to memory-safety mistakes like use-after-free and buffer overruns. A wrong pointer does not raise an error; it segfaults the process or silently corrupts data.

Every experiment pays a toll

In C, each try–look–adjust cycle needs a full compile, link, and run before you see a single result. Data science lives in a loop measured in seconds; a build cycle stretches it to minutes. The iteration speed that makes analysis creative is precisely what the language takes away.

And the talent pool contracts

The people who need computation most — statisticians, biologists, analysts — will never manage malloc and free daily. Choosing C++ for a data team means choosing a small, expensive, hard-to-hire pool and excluding your own domain experts.

ONE TASK, TWO LANGUAGES

# R: the statistician writes one line y <- sqrt(x*x + 1) # C: the engineer manages the machine double *y = malloc(n * sizeof(double)); if (!y) perror("alloc failed"), return -1; for (size_t i = 0; i < n; i++) y[i] = sqrt(x[i]*x[i] + 1.0); free(y); // forget this line → memory leak

Both compute the same thing. One expresses the mathematics; the other manages the machine — allocation, error handling, the loop, and the cleanup you must not forget.

THE TWIST

R was never written in R

»

The interpreter is C

Every expression you type in R is parsed and evaluated by a C program. The R you love is a friendly face over a compiled engine — the REPL itself is C.

»

The mathematics is Fortran

Linear algebra — the hottest code in statistics — is delegated to BLAS and LAPACK: fifty-year-old Fortran routines that hardware vendors have tuned ever since. Matrix multiply in R runs at essentially hardware speed.

»

Hybrid by design

R was born as a high-level face over low-level engines. Its speed never came from R code — it came from what R was standing on. That is the exact pattern this talk is about.

YOU WRITE

21,000+ CRAN packages 2,000+ Bioconductor accepted in FDA submissions

So when someone asks "can R be fast?" — history already answered: R has been riding on C for thirty years.

STATISTICAL & TABULAR ML

Where R is a first-class champion

Statistics is the native language

lm, glm, survival, lme4 — the models statisticians actually trust are built in and first-class, with formula syntax. Not bolted on through wrappers: the language was designed around them.

State-of-the-art tabular learners

xgboost, glmnet, randomForest. On tabular data, gradient boosting still beats deep networks — and R runs it natively, at speed.

The grammar of graphics

ggplot2 defined layered visualization so completely that Python cloned the idea — plotnine is a direct port. The concept flowed from R outward.

06

Trusted where it matters most

Pharma runs R end to end, and regulators accept R submissions. In clinical trials and reporting, R is the incumbent, not the challenger.

For anything statistical or tabular, R matches or beats Python. The frontier problem is not here — it is one slide away.

GENERATIVE & AGENTIC AI

Possible in R? Yes. Served by R? No.

NOTHING TECHNICAL BLOCKS R

»

An LLM is an HTTPS call with a JSON body. R has spoken HTTP natively for decades — curl, httr2. Nothing exotic is required.

»

Token streaming is line-buffered text. Server-sent events parse the same way in any language; R can read a stream as well as Python can.

»

Embeddings are linear algebra — the very thing R was born doing, delegated to compiled BLAS under the hood.

BUT THE SHELF IS THIN

»

Model labs ship Python SDKs on day one. R wrappers arrive later — if at all — maintained by volunteers, not by the lab.

»

Existing options like ellmer and tidyllm wrap chat APIs well — and stop there. Chat is one node of an agent, not the agent.

»

No graph runtime for branching workflows, no tool-loop engine, no vector store layer, no evaluation harness. The infrastructure layer simply does not exist yet.

Agentic AI in R was never impossible. It was simply never built. So we built it.

THE INDUSTRY'S OPEN SECRET

Every fast high-level stack is a skin over C

»

CPython is C

Python's own interpreter is a C program. Every Python line ever executed was executed by C. Python people have been running C daily for thirty years — they just never saw it.

»

The scientific stack is compiled

NumPy, pandas, and scikit-learn cores are C and C++. PyTorch is C++ behind a Python front end. TensorFlow: same story. The Python you benchmark is mostly compiled code already.

»

R's speed core is compiled too

data.table is C, Stan is C++, DuckDB is C++. CRAN's fastest packages all follow one pattern: an R API over a compiled engine. The hybrid is not exotic — it is the house style of high-performance R.

2,600+

CRAN packages ship compiled C++ through Rcpp today — making it the most depended-upon package in the entire R ecosystem.

50–100×

Typical measured speedup when a hot R loop moves into Rcpp C++ — with identical results, because the glue is generated, not hand-written.

So the fix is not exotic. It is the proven industrial pattern, applied deliberately to a domain it has never fully claimed: agentic AI.

WHY AGENTS SPECIFICALLY NEED IT

Four things a pure interpreter cannot give

01

True parallel fan-out

An agent swarm is an embarrassingly parallel workload. In a compiled engine every specialist runs on a real std::thread, with no global lock serializing their thinking. Twenty agents, twenty cores, one schedule.

02

Streaming without interpreter hops

Server-sent events are parsed token by token inside C++; callbacks cross into R only when there is something worth saying. Per-token latency stays flat even as throughput accelerates.

03

Deterministic execution

Graph routing, state merges, and tool dispatch run with zero GC pauses and zero warmup. An agent that ran a hundred times behaves identically on run one hundred and one — which is exactly what testing and evaluation require.

04

Vector search at native speed

The HNSW index over your documents is built and queried in-process, in compiled code. Retrieval answers in microseconds inside the running agent loop — not as a network hop out to another service.

These are exactly the four bottlenecks that slow agentic systems down. The hybrid pattern removes them by construction, not by tuning.

BUILD PIPELINE

From two source trees to one package

1

Write both sides. R files define the user API; C++ files define the engine. Attributes mark exactly what crosses the bridge.

2

Generate the glue. compileAttributes() scans the C++ and writes the R wrappers automatically — no hand-written bindings anywhere.

3

Compile with GCC. g++ -std=c++20 builds the engine into a native DLL, with vendored headers included.

4

Install as one package. R CMD INSTALL ships R code and the binary together. Three hard dependencies only: Rcpp, jsonlite, processx.

5

Verify relentlessly. 56 test files, live provider runs, crash probes, stress tests, and a clean R CMD check.
